# 神奇寶貝綠寶石連接線協定細節

[繁中設計說明](gba-pokemon-cable.zh-TW.md) · [English overview](gba-pokemon-cable.md) · [English details](gba-pokemon-cable-details.md) · [術語表](gba-link-glossary.zh-TW.md)

本文件補充英文版《神奇寶貝綠寶石》連接線設定檔的資料傳送、同步界線和測試細節。玩家使用方式與目前支援狀態請看[繁中設計說明](gba-pokemon-cable.zh-TW.md)。

## 適用範圍與啟動資訊

核心選項 `lotusgba_link_device` 選擇 `Wireless Adapter` 或 `Link Cable`；切換後需重新載入內容。ROM 識別會選擇相容的連線設定檔，但不會覆蓋裝置選項。連接線遠端設定檔目前只處理英文版綠寶石 `BPEE`。

Netplay 啟動時會交換 ROM 身分、連線時鐘（session clock）、卡帶儲存區大小和裝置選擇，不交換 SRAM 內容。兩端裝置選擇不一致時連線會被拒絕。各端使用各自遊戲和存檔；目前前端要求 ROM 相同。開始連線沿用現有的遊戲重啟行為。

## 交握與資料傳送

英文版綠寶石的交握仍由遊戲負責。核心在初始搜尋及交握期間使用實際收到的對等端資料，不依裝置準備狀態推測 `0xB9A0`。一次有效的初始回覆可以是 `0x0000`。遊戲在進入交易座位後會重新建立連線並交換身分；進入大廳不代表第二次交握完成。

交握完成後，Netplay 傳送完整八字資料命令，不會為每一個 SIO 資料字另做一次網路請求／回覆。核心仍在本機更新序列暫存器、傳輸時序與中斷，讓遊戲看到它預期的 SIO 介面。這是針對該遊戲的相容實作，不是實體連接線電氣時序的完整模擬。

### 封包分組與檢查碼

遊戲的每組資料由前一組合併檢查碼開始，後接八個資料字。第一組檢查碼依遊戲初始狀態不驗證，之後的錯誤會設定 SIO 錯誤狀態。網路封包檢查碼只驗證單一傳送者的八個資料字；遊戲序列檢查碼驗證雙方前一個本機資料組。兩種檢查碼不能互換。

封包在資料組邊界才交付；若封包在一組傳送中途到達，先留在佇列，避免插入已開始的資料組或改寫遊戲已讀到的檢查碼。全零閒置命令不傳網路，也不佔用訊息序號。

### ACK 與佇列額度

LotusGBA 使用 RetroArch Netpacket 的可靠模式，交由前端處理封包送達與順序；核心不重做 TCP 的丟包重送。Netplay 的 admission ACK 是另一層的接收額度回覆：只有接收端把資料放進系統佇列後才回覆，用來限制尚未交給遊戲處理的資料量。它不代表綠寶石已讀取資料、檢查碼正確、完成一段遊戲資料，或同意交易。

每個方向最多保留 32 個尚未確認的資料區塊。接收佇列暫滿時，前端保留有序封包並暫停回覆額度；核心端若耗盡額度，會在資料組邊界保留不可變區塊並暫停遊戲，直到額度回補。此設計以有界佇列和背壓避免丟包或重排；網路進度不對稱時，遊戲端仍可能等待。

## 遊戲層界線

遊戲程式仍處理玩家身分、隊伍交換、確認、取消和關閉：

| 階段 | 遊戲端責任 |
|---|---|
| 身分 | 收到並重組每位玩家的識別資料後，才標記玩家已收到。 |
| 隊伍交換 | 遊戲要求雙方資料，等兩端資料旗標都完成再前進。 |
| 確認與完成 | 依遊戲內控制訊息和雙方準備狀態決定何時完成。 |
| 取消與關閉 | 遊戲決定取消和關閉；已關閉嘗試的舊資料不可進入下一次連線。 |

遊戲的序列 watchdog 與遊戲任務逾時是不同計時器。例如來源顯示子端序列中斷檢查與玩家身分等待各有自己的影格／任務上限；觀察到通信錯誤，不能單憑錯誤畫面推斷是哪一層造成。

## 同步和重設取捨

在尚未進入緩衝傳送前，初始搜尋可能每一個 VBlank 都等待一個真實對等端資料字。這會讓每次網路往返都延長交握時間。核心在原始傳輸階段限制子端遊戲的影格超前量；進入緩衝傳送後，雙方可各自推進，不再逐字等待網路。

緩衝交握使用 `0x8FFF`／`0xB9A0` 啟動；遊戲要求玩家數量穩定後才接受主端交握。核心觀察子端的遊戲連線狀態，必要時在子端仍交握時於本機重做已觀察到的主端交握。這是已知的遊戲相容策略，不是硬體行為主張；合成 callback 測試覆蓋拒絕第一次交握後的處理。

`DisableSerial`／`EnableSerial` 在遊戲仍處於多人連線狀態時寫入 `SIOCNT=0x2000`。連線設定檔將此視為遊戲解析器重設：停止子端自動傳送、丟棄部分或排隊資料組，並重新進行初始搜尋。網路命令序號與本機虛擬序列傳輸次數分開；這一點依賴可靠有序的 Netplay 通道。

這些調整能減少穩定傳送階段每個資料字的網路往返，但不能讓初始交握、遊戲層關卡、任意延遲或斷線變成即時成功。它們是英文版綠寶石相容策略，不是通用連接線模擬。

## 測試與人工觀察

合成系統測試涵蓋雙向檢查碼、完整資料組延遲交付、交握時子端影格超前量、重設／重新啟動、SIO 暫存器保存、佇列額度和序號錯誤。前端測試另涵蓋裝置選項、連線設定檔啟動和裝置不一致拒絕。這些測試沒有執行商業遊戲，不能代替遊戲交易、對戰或 WAN 驗收。

遊戲觀察包含本機雙 ROM 子系統交易、兩個 RetroArch localhost 實例的受控延遲交易，以及有限 relay 交易。各次條件和完成階段不同，詳情請看[繁中設計說明的結果表](gba-pokemon-cable.zh-TW.md#目前有哪些遊戲檢查)。完整測試案例、trace 欄位和來源索引另見英文[實作參考](gba-pokemon-cable-implementation-reference.en.md)。
