# 神奇寶貝綠寶石 RFU 無線連線：設計與驗證

[English translation](gba-rfu-protocol.md) · [協定細節（繁中）](gba-rfu-protocol-details.zh-TW.md) · [GBA 連線術語中英對照](gba-link-glossary.zh-TW.md)

## 先看重點

RFU 是《神奇寶貝綠寶石》使用 GBA Wireless Adapter 連線時的一套資料交換規則。LotusGBA 目前只針對英文版綠寶石做實驗性連線支援，不能視為通用的 GBA 無線連線功能。

英文版綠寶石已完成一次 LAN 交換，雙方各自離線重開存檔後都確認了交換結果；目前版本另有一次中繼交換成功回報。LAN 和中繼都曾完成 Colosseum 單打。依測試回報，中繼交換後雙方也各自離線重開並確認了交換結果。

## 實機連線時發生什麼事

實體 GBA 會連接 Wireless Adapter。遊戲把連線資料交給轉接器，由轉接器透過無線電送到另一台 GBA。另一端的遊戲收到資料後，仍由遊戲判斷玩家身分、交換是否完成，以及何時結束連線。

## LotusGBA 如何連接兩端

LotusGBA 不模擬無線電波。每位玩家各自執行一份遊戲；核心在本機模擬遊戲所連接的轉接器，再透過 RetroArch Netplay 把遊戲連線資料送到另一端：

```text
遊戲 A ⇄ LotusGBA A ⇄ RetroArch Netplay ⇄ LotusGBA B ⇄ 遊戲 B
```

兩端的遊戲各自運作並保有自己的存檔。Netplay 傳送的是遊戲連線資料，不會傳送或合併整份存檔。交換是否成功仍由遊戲判斷，核心不會自行宣告交易完成。

## 為了讓連線更順，核心做了什麼取捨

實體 Wireless Adapter 透過無線電交換資料；LotusGBA 改由 Netplay 傳送資料。為減少等待，核心不要求每次本機送出資料後，都先等一次網路往返才讓遊戲繼續。這能減少部分等待，但資料交換時機和實體轉接器不同。

遊戲在身分確認、交易確認等步驟仍要等另一端。接收佇列滿時，核心會暫停後續傳送並保留資料順序，因此網路延遲或另一端進度較慢時，遊戲仍可能停頓。這些調整是為綠寶石連線所做的相容處理，不代表已精確重現硬體，也不能據此推定可支援的網路延遲範圍。
